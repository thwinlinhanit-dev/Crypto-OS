## Open questions (not decisions — require owner input)

- **OQ-1 (climax-no-trade layer):** Pine draws the "climax (no trade)" dot as `isClimax and sigDir == 0`, i.e. *after* `sideMode` / `useLong*` / `useShort*` strategy filters (with `sideMode="Long only"`, a valid TOP still renders a dot). SPEC §6.3 says only "isClimax bars without a signal". Pre-filter or post-filter? Blocks exact parity of that plot layer only.
- **OQ-2 (`fail_mode` value mapping):** Pine option strings `"Failed bounce (new)"` / `"Legacy (v1)"` vs SPEC §6.3 `"failed_bounce"` / `"legacy_v1"`. Mapping to be codified in the detector spec and `config/defaults.yaml`.
- **OQ-3 (`engine_version` format):** The spec requires `engine_version` in every stored result (PD-6) but never defines its format or bump policy. Interim value: constant `"0.1.0"` from `engine/versions.py`. Needs owner confirmation (semver? spec §-id?) before any result is treated as reproducible evidence.
- **OQ-4 (`status` semantics):** `/v1/status` reports `ok` only when the database answers and `degraded` otherwise. The spec does not define further degradation classes (migrations pending, data missing). Fine as-is for M0; confirm before M1 freezes the contract.
- **OQ-5 (zero-volume fraction):** §4.6 is silent on a state for zero-volume fraction ≥ 0.1%. Interim: `YELLOW`.
- **OQ-6 (OHLC sanity):** §4.6's OHLC triple does not check `o <= h` / `l <= c`. Confirmed *not* checked (PD-4 — no rule invented); owner to confirm the spec text is complete.
- **OQ-7 (decreasing time):** §4.6 names no state for strictly non-monotonic time. Interim: `RED` (INTERPRETATION: ordering corruption is invalid alongside duplicates).
- **OQ-8 (RSI default length):** §5 defines RSI only as "Wilder/rma" and gives no length; TradingView's default is 14. Not documented in `config/defaults.yaml` (`indicators.rsi.length: null`): the request must supply a length, otherwise the API answers 422 (PD-11; PD-4 forbids inventing the default). Confirm whether M3 parity adopts 14 as a documented default.
- **OQ-9 (indicator response body):** §11 lists `/v1/indicators` query parameters only. Interim contract in D-011; confirm before it becomes a client dependency.
- **OQ-10 (layout persistence medium):** §12 says "layout persisted" without naming a store. Interim: `localStorage` (D-012); confirm if layouts must survive browsers/devices.
- **OQ-11 (partial candle windows):** §11 defines `DATA_INCOMPLETE` but not candle-window behavior over gaps. Interim: serve + shade (D-013).
- **OQ-12 (`1W` availability):** derived `1W` parts exist but the seed writes no RESAMPLE manifest (m1_data §7), so `/v1/candles?tf=1W` answers `DATA_UNAVAILABLE` and the chart does not offer `1W`. Confirm whether a RESAMPLE job should run at seed time.
- **OQ-13 (`highest`/`lowest` warm-up value):** §5 line 228 says "null during warm-up" but Pine's `ta.highest` returns a partial extremum before bar n-1 is reached. Interim: null until n values exist (the §5 `sma` rule, line 229). Layer 1 does not export these columns; confirm against Pine before any detector consumes them.
- **OQ-14 (pivot tie rule vs Pine):** D-016 pins strict inequality on both sides. Pine's `ta.pivotlow` tie behaviour is unverified; confirm on a future export layer that carries pivot columns.
- **OQ-15 (documented platform differences):** the initial table (`tv_export_rounding` at ~6-8 significant digits, `tv_na_vs_engine_null` inside the first 500 bars) is an INTERPRETATION pending the owner's real export; entries may be added or removed after the first `make parity` run against it (spec line 592 requires each entry to carry a design-note anchor, which `engine/parity/platform_differences.py` enforces).

Unnumbered M1 questions (metadata vocabulary, `STALE_GRACE_BAR_LENGTHS`, exclusions after `REPAIRED`) are tracked in [specs/design/m1_data.md](../specs/design/m1_data.md) §13.
